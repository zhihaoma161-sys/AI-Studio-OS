# 背包系统 - 系统详细设计案

## 一、系统定位与设计目的

- **系统定位**：纯仓储工具型容器。背包是玩家查看、使用、丢弃所有非战斗类道具（材料、礼物、消耗品）的唯一存储与管理界面。系统不包含任何角色模型展示、情感互动或社交展示功能，所有操作以高效、低干扰为最高设计准则。
- **设计目的**：为玩家提供清晰、高效、零干扰的道具管理体验。所有核心操作（查看详情、使用消耗、丢弃、堆叠整理）必须在一级界面内完成，禁止任何深层嵌套的二级或三级菜单。背包界面设计以简洁为优先，确保不遮挡战斗或大厅中的角色展示，严格遵循项目宪法中“严禁大面积遮挡角色模型”的红线。
- **入口规则**：玩家完成新手引导后，主界面自动解锁背包入口图标。该入口为全局常驻入口，不随任何系统状态变化而隐藏或置灰。
- **数据归属**：背包系统不持有任何独立的经济循环。所有道具的产出与消耗均通过与其他系统的接口联动完成，背包仅作为道具的“终点站”与“起点站”。

## 二、核心规则与玩法机制

### 2.1 道具分类与筛选

- **【前置条件】**：玩家背包数据加载完成，`bag_item_list` 非空（若为空，直接跳转至边界处理）。
- **【流转逻辑】**：
    1. 系统在背包界面顶部渲染五个一级分类标签，固定顺序为：“材料”、“礼物”、“消耗品”、“任务道具”、“其他”。
    2. 每个一级标签下可包含子分类（如“材料”下分“突破材料”、“技能材料”），子分类以折叠/展开形式展示在标签栏下方。
    3. 玩家点击任意一级标签，系统立即筛选 `bag_item_list`，仅显示 `item_category_id` 等于该标签ID的道具条目。
    4. 玩家可点击排序按钮，选择按稀有度（N/R/SR/SSR）升序或降序排列当前列表。排序规则记录至 `current_sort_order`。
- **【数据状态变化】**：
    - `current_bag_category_id` 更新为玩家所选标签的ID。
    - `current_sort_order` 更新为玩家所选排序规则（`[SORT_RARITY_ASC]` 或 `[SORT_RARITY_DESC]`）。
    - 列表渲染引擎根据 `current_bag_category_id` 和 `current_sort_order` 重新生成显示列表。
- **【表现层反馈】**：
    - 选中标签高亮显示，其余标签恢复默认样式。
    - 列表区域以网格视图（固定4列）重新渲染，道具图标按排序规则排列。
    - 若切换标签时列表为空，显示占位图与提示文字。
- **【边界与异常兜底】**：
    - **空分类处理**：若玩家点击的标签下无任何道具，列表区域显示占位图（灰色半透明背景 + 空箱子图标），并显示文字“该分类暂无道具”。标签本身仍可点击，不置灰。
    - **排序无结果**：排序操作不影响空分类的显示逻辑，若当前分类无道具，排序按钮可点击但无实际效果。
    - **数据加载失败**：若 `bag_item_list` 加载失败（如网络中断），界面显示加载中动画，并每 `[RETRY_INTERVAL]` 秒自动重试。重试 `[MAX_RETRY_COUNT]` 次后仍失败，显示“数据加载失败，请稍后重试”提示，并提供“刷新”按钮。

### 2.2 道具操作

#### 2.2.1 查看详情

- **【前置条件】**：玩家点击任意道具图标。
- **【流转逻辑】**：
    1. 系统根据 `item_id` 从道具配置表 `item_config_table` 中读取该道具的完整信息。
    2. 在屏幕中央弹出详情浮窗，浮窗为半透明毛玻璃背景，不遮挡主界面角色展示。
    3. 浮窗内容固定包含：道具图标（高精度2D插画）、道具名称、道具描述、稀有度标签（N/R/SR/SSR对应颜色）、当前持有数量、来源说明（如“来源：关卡[STAGE_ID]掉落”）。
- **【数据状态变化】**：无后台数据变化。
- **【表现层反馈】**：浮窗以淡入动画出现，点击浮窗外任意区域或点击关闭按钮，浮窗以淡出动画消失。
- **【边界与异常兜底】**：
    - **配置缺失**：若 `item_config_table` 中未找到该 `item_id`，浮窗显示“道具信息异常”提示，并提供“联系客服”按钮（调用客服系统接口）。
    - **并发点击**：若玩家在浮窗动画播放期间快速点击多个道具，系统仅响应最后一次点击，忽略中间操作。

#### 2.2.2 使用/消耗

- **【前置条件】**：
    - 道具的 `item_usable_flag` 为 `true`（即道具为消耗品，如体力药水、经验书）。
    - 玩家当前持有该道具数量 `item_count` 大于 `0`。
- **【流转逻辑】**：
    1. 在详情浮窗中，若道具可被使用，显示“使用”按钮（蓝色高亮）。
    2. 玩家点击“使用”按钮，系统弹出二次确认弹窗，弹窗内容包含：道具图标、道具名称、使用效果描述（如“恢复 `[STAMINA_RECOVER_VALUE]` 体力”）、确认按钮、取消按钮。
    3. 玩家点击确认按钮，系统调用 `use_item(item_id, 1)` 接口。
    4. 接口内部逻辑：检查 `item_count` 是否大于等于 `1`，若满足，则 `item_count` 减 `1`，并触发道具对应的效果逻辑（如调用体力系统接口 `add_stamina([STAMINA_RECOVER_VALUE])`）。
    5. 若使用后 `item_count` 归零，该道具条目从列表中移除。
- **【数据状态变化】**：
    - `item_count` 减少 `1`。
    - 若道具效果涉及其他系统（如体力），对应系统的数据同步更新。
- **【表现层反馈】**：
    - 确认弹窗以淡入动画出现。
    - 使用成功后，弹窗关闭，道具图标上显示“-1”飘字动画。
    - 若使用后道具归零，列表刷新，该道具图标消失。
    - 若使用失败，弹窗显示错误提示（如“使用失败，请重试”）。
- **【边界与异常兜底】**：
    - **不可使用道具**：若 `item_usable_flag` 为 `false`（如任务道具），“使用”按钮置灰，鼠标悬停时提示“该道具不可使用”。
    - **数量不足**：若玩家在确认弹窗打开期间，通过其他途径消耗了该道具（极端并发情况），点击确认后系统检测 `item_count` 为 `0`，弹窗显示“道具数量不足”提示，并自动关闭。
    - **效果执行失败**：若道具效果逻辑执行失败（如体力已满，调用 `add_stamina` 返回错误码），系统回滚 `item_count` 的减少操作，并显示“使用失败：[具体原因]”提示。
    - **网络中断**：若在调用 `use_item` 接口时网络中断，系统显示“网络异常，请重试”提示，不扣除道具，不触发效果。

#### 2.2.3 丢弃

- **【前置条件】**：
    - 道具的 `item_discardable_flag` 为 `true`（即道具可被丢弃）。
    - 玩家当前持有该道具数量 `item_count` 大于 `0`。
- **【流转逻辑】**：
    1. 在详情浮窗中，若道具可被丢弃，显示“丢弃”按钮（红色警告色）。
    2. 玩家点击“丢弃”按钮，系统弹出二次确认弹窗，弹窗内容包含：警告图标、文字“确定要丢弃该道具吗？丢弃后不可恢复。”、道具图标、道具名称、确认按钮（红色）、取消按钮。
    3. 玩家点击确认按钮，系统调用 `discard_item(item_id, 1)` 接口。
    4. 接口内部逻辑：检查 `item_count` 是否大于等于 `1`，若满足，则 `item_count` 减 `1`，道具从背包中永久移除。
    5. 若丢弃后 `item_count` 归零，该道具条目从列表中移除。
- **【数据状态变化】**：
    - `item_count` 减少 `1`。
    - 道具从 `bag_item_list` 中移除（若数量归零）。
- **【表现层反馈】**：
    - 确认弹窗以淡入动画出现，背景变暗以强调警告性。
    - 丢弃成功后，弹窗关闭，道具图标上显示“-1”飘字动画（红色）。
    - 若丢弃后道具归零，列表刷新，该道具图标消失。
- **【边界与异常兜底】**：
    - **不可丢弃道具**：若 `item_discardable_flag` 为 `false`（如关键任务道具），“丢弃”按钮置灰，鼠标悬停时提示“该道具不可丢弃”。
    - **数量不足**：与“使用”操作相同，若并发导致数量不足，弹窗显示“道具数量不足”提示。
    - **网络中断**：与“使用”操作相同，不扣除道具，显示“网络异常，请重试”提示。

#### 2.2.4 堆叠

- **【前置条件】**：玩家获得新道具时，系统自动触发堆叠逻辑。
- **【流转逻辑】**：
    1. 当系统调用 `add_item(item_id, count)` 时，首先遍历 `bag_item_list`，查找 `item_id` 相同且 `current_stack_size` 小于 `[MAX_STACK_SIZE]` 的已有堆叠。
    2. 若找到可用堆叠，将新道具数量填充至该堆叠，直到堆叠满或新道具数量耗尽。
    3. 若所有已有堆叠均已满，或未找到相同 `item_id` 的堆叠，系统自动创建新的堆叠条目，占用一个新的背包格子。
- **【数据状态变化】**：
    - 已有堆叠的 `current_stack_size` 增加，上限为 `[MAX_STACK_SIZE]`。
    - 若创建新堆叠，`bag_item_list` 新增一条记录，`occupied_slots` 增加 `1`。
- **【表现层反馈】**：无直接UI反馈，道具图标上显示的持有数量自动更新。
- **【边界与异常兜底】**：
    - **背包满**：若 `occupied_slots` 已达到 `bag_max_slots`，且无法通过堆叠容纳新道具，`add_item` 接口返回错误码 `[ERROR_BAG_FULL]`，调用方（如战斗结算系统）需处理该错误，将道具转入邮件系统。
    - **堆叠上限溢出**：若新道具数量超过单个堆叠剩余空间，系统自动拆分，创建多个堆叠，确保每个堆叠不超过 `[MAX_STACK_SIZE]`。

### 2.3 背包容量

- **【前置条件】**：玩家首次获得道具时，背包自动初始化。
- **【流转逻辑】**：
    1. 背包初始容量为 `[INITIAL_BAG_CAPACITY]` 格，记录于 `bag_max_slots`。
    2. 每格可堆叠同ID道具，堆叠上限为 `[MAX_STACK_SIZE]`。
    3. 玩家可通过两种方式扩容：
        - **消耗道具**：使用“背包扩容券”（`[EXPAND_ITEM_ID]`），每次使用消耗 `1` 个，永久增加 `[EXPAND_SLOTS_PER_USE]` 格容量。
        - **付费货币**：直接消耗 `[PREMIUM_CURRENCY]`，每次扩容消耗 `[EXPAND_COST_CURRENCY]`，永久增加 `[EXPAND_SLOTS_PER_USE]` 格容量。
    4. 扩容操作入口位于背包界面底部，显示当前容量（`occupied_slots` / `bag_max_slots`），并配有“扩容”按钮。
    5. 玩家点击“扩容”按钮，弹出扩容选择弹窗，提供两种扩容方式选项，并显示当前持有数量（如“背包扩容券 x [持有数量]”）。
    6. 玩家选择一种方式并确认后，系统调用 `expand_capacity([EXPAND_SLOTS_PER_USE])` 接口。
- **【数据状态变化】**：
    - `bag_max_slots` 增加 `[EXPAND_SLOTS_PER_USE]`。
    - 若使用扩容券，`[EXPAND_ITEM_ID]` 的 `item_count` 减少 `1`。
    - 若使用付费货币，`[PREMIUM_CURRENCY]` 减少 `[EXPAND_COST_CURRENCY]`。
- **【表现层反馈】**：
    - 扩容成功后，底部容量显示更新为新的 `bag_max_slots`，并播放“+[EXPAND_SLOTS_PER_USE]”飘字动画。
    - 若扩容券不足，对应选项显示“数量不足”并置灰。
    - 若付费货币不足，对应选项显示“货币不足”并置灰，并提供“前往充值”跳转链接（指向商城充值界面）。
- **【边界与异常兜底】**：
    - **背包已满**：当 `occupied_slots` 等于 `bag_max_slots` 时，玩家无法获得任何新道具。系统在玩家尝试获得道具时（如战斗结算、领取邮件）弹出提示“背包已满，请先清理或扩容”，并提供“前往背包”跳转按钮。战斗结算时若背包满，道具自动进入临时“邮件”系统，保留 `[MAIL_RETENTION_DAYS]` 天。
    - **扩容上限**：背包容量存在硬上限 `[BAG_CAPACITY_HARD_CAP]`，当 `bag_max_slots` 达到该值时，“扩容”按钮置灰，提示“背包容量已达上限”。
    - **扩容券不足**：若玩家选择使用扩容券但持有数量为 `0`，选项置灰，提示“背包扩容券不足，请前往活动或商城获取”。
    - **付费货币不足**：若玩家选择使用付费货币但余额不足，选项置灰，提示“[PREMIUM_CURRENCY]不足，请前往充值”。

## 三、表现层与角色展示联动

- **【核心原则】**：背包系统为纯工具型界面，不展示任何角色模型、立绘或3D场景。所有UI设计以简洁、高效为优先，确保不遮挡主界面角色展示。
- **UI风格**：
    - 采用半透明毛玻璃背景，背景色为深色半透明（`[UI_BG_COLOR]`），确保道具图标清晰可见。
    - 道具图标采用高精度2D插画，统一尺寸为 `[ICON_SIZE]` x `[ICON_SIZE]` 像素。
    - 列表采用网格视图，固定4列，支持垂直滑动浏览。滑动条为细窄样式，不占用过多空间。
- **运镜设计**：无特殊运镜。背包界面为独立全屏UI，打开时覆盖主界面，关闭时恢复主界面显示。不存在任何与角色或场景的叠加或联动。
- **物理反馈**：无任何物理抖动、角色互动反馈或触觉反馈。所有操作反馈仅限于UI层面的动画（如按钮点击缩放、飘字、弹窗淡入淡出）。
- **擦边底线**：背包系统不涉及任何角色互动、擦边内容或暗示性设计。所有道具图标与描述均符合项目宪法中的尺度分级底线。

## 四、经济循环与商业化埋点

- **免费产出**：背包系统本身不产出任何资源或道具。所有道具的来源均为其他系统（战斗掉落、活动奖励、任务完成、商城购买）。背包仅作为道具的存储容器。
- **付费埋点**：
    - **背包扩容**：玩家可使用付费货币 `[PREMIUM_CURRENCY]` 直接扩容，或通过活动/任务获得免费扩容券 `[EXPAND_ITEM_ID]`。扩容券也可在商城中以 `[PREMIUM_CURRENCY]` 或 `[FREE_CURRENCY]` 购买。
    - **道具礼包**：商城可出售包含稀有道具的礼包，购买后道具直接调用 `add_item` 接口进入背包。礼包内容可包含扩容券、高级材料、限定礼物等。
- **资源循环**：背包是道具的“终点站”与“起点站”。所有系统产出的非战斗道具最终流入背包，所有系统消耗的道具从背包中扣除。背包系统不产出任何抽卡资源（如 `[GACHA_CURRENCY]`），严格遵循项目宪法中的商业化倾向。

## 五、旧系统与数据联动

- **道具产出系统**（战斗、活动、任务、商城）：
    - 所有新获得道具必须调用背包接口 `add_item(item_id, count)`。
    - 若 `add_item` 返回错误码 `[ERROR_BAG_FULL]`，产出系统需将溢出道具转入邮件系统，调用邮件接口 `send_mail(player_id, item_id, count, [MAIL_RETENTION_DAYS])`。
    - 产出系统需在调用 `add_item` 前，检查 `item_id` 是否存在于道具配置表 `item_config_table` 中，若不存在，记录错误日志并跳过该道具。
- **道具消耗系统**（角色养成、宿舍送礼、战斗准备）：
    - 所有消耗道具的操作必须调用背包接口 `remove_item(item_id, count)`。
    - 若 `remove_item` 返回错误码 `[ERROR_ITEM_NOT_ENOUGH]`，消耗系统需向玩家提示“道具不足”，并中断当前操作。
    - 消耗系统需在调用 `remove_item` 前，检查 `item_count` 是否足够，避免不必要的接口调用。
- **邮件系统**：
    - 背包满时，溢出的道具进入邮件系统，邮件附带道具ID与数量。
    - 玩家在邮件系统中领取道具时，邮件系统调用 `add_item(item_id, count)`。
    - 若领取时背包仍满，`add_item` 再次返回 `[ERROR_BAG_FULL]`，邮件系统需提示玩家“背包已满，请先清理”，并保留邮件。
- **商城系统**：
    - 玩家购买道具礼包后，商城系统调用 `add_item(item_id, count)` 将道具加入背包。
    - 若背包满，商城系统需提示玩家“背包已满，购买失败”，并回滚货币扣除操作。
    - 商城系统需在购买前，调用背包接口 `check_bag_space(item_id, count)` 预检是否有足够空间容纳新道具。
